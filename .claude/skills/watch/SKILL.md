# /watch — 停滞監視と自律前進

使い方: `/watch <対象> [間隔]`

- `<対象>`: PR 番号・PR URL、ブランチ名、タスクファイル（例 `TASKS.md`）、または作業内容の説明
- `[間隔]`: `30m` / `2h` など。省略時は `30m`

## 1 回のチェックで行うこと

### 1. 状態を集める
対象に応じて現在の状態を確認する。

- **PR**: GitHub MCP ツールで CI 結果、レビューコメント、マージ可否（コンフリクト）、最終更新日時
- **ブランチ**: `git fetch` → 直近コミット、未プッシュ差分、ビルド・lint・テストの結果
- **タスクファイル**: 未完了項目と、その項目の最終更新

前回チェックの結果は `.claude/watch/STATE.md` に記録されている。前回と比べて何が変わったかを見る。

### 2. 止まっているか判定する
次のどれかに当たれば「停滞」とみなす。

- CI が赤のまま、またはコンフリクトのまま
- 未対応のレビューコメントがある
- 前回チェックから進捗がなく、残タスクがある
- エラーや失敗ログで作業が中断している

停滞がなければ STATE.md に「変化なし」と記録して手順 6 へ進む。ユーザーには報告しない。

### 3. GPT と協議する
停滞の要約を作り、GPT に相談する。

```bash
node .claude/skills/watch/scripts/ask-gpt.mjs <<'EOF'
## 対象
...
## 現状（事実のみ: エラーログ抜粋、CI 結果、差分の要点）
...
## 止まっている理由についての Claude の見立て
...
## Claude の案（複数あれば列挙）
...
EOF
```

- GPT は「原因分析」「取るべき案と理由」「リスク」「人間の判断が必要か」を返す
- GPT の回答はあくまで参考意見として扱う。自分の分析と突き合わせて、根拠のより強い案を採る
- 意見が割れたときは、論点を絞って 1〜2 往復まで再質問する（`--followup` で前回の文脈を引き継ぐ）
- GPT が未設定（終了コード 2）、または接続できないとき（終了コード 3）: その旨を STATE.md に 1 回だけ記録し、Claude 単独で判断して続行する

### 4. 実行する
決めた案を実行する。

- 修正 → リポジトリのチェック（lint / typecheck / build / test）を通す → コミット → 指定ブランチへ push
- push 前に差分を見直し、CI に落とされる要素がないか確認する
- テストをスキップ・無効化して緑にすることはしない

### 5. 具申するかどうか
次の場合**だけ**ユーザーに具申する。それ以外は黙って進める。

- 本番デプロイ、データ削除、force push、課金、外部への公開など、取り消しにくい操作が必要
- 仕様や方針、プロダクトとしての判断が必要（どちらの挙動が正しいか決められない）
- 認証情報、権限、アクセス許可が足りない
- Claude と GPT の意見が重要な点で割れ、再協議しても収束しない
- 同じ停滞に 3 回続けて手を打っても解消しない

具申には「何が止まっているか」「検討した案（Claude 案・GPT 案）」「推奨案と理由」「必要な判断」を短くまとめる。

### 6. 記録して次回を予約する
`.claude/watch/STATE.md` に今回のチェック結果を追記する（日時、状態、行った対応、GPT 協議の要約）。

次回チェックの予約:
- `/loop` 経由で動いている場合は `ScheduleWakeup` で次回を指定する
- それ以外は `send_later` で `[間隔]` 後に「`/watch <対象> <間隔>` の定期チェック」を自分宛てに送る

止める条件:
- 対象が完了した（PR がマージ／クローズ、タスクがすべて完了）
- ユーザーに止めるよう言われた
- 「変化なし」が 3 回続いた → ユーザーに一言だけ伝えて停止

## 設定

### ローカル GPT（この PC 上の Ollama / LM Studio など）を使う場合
ローカル GPT には PC 上で動く Claude Code セッションからしか届かない。クラウドセッションからは使えない。
Claude Desktop アプリ、またはリポジトリのフォルダで `claude remote-control` を起動して、そのセッションで `/watch` を使う。

環境変数（PC 側で設定）:
- `OPENAI_BASE_URL`: OpenAI 互換エンドポイント。Ollama は `http://localhost:11434/v1`、LM Studio は `http://localhost:1234/v1`
- `OPENAI_MODEL`: モデル名（必須。例 `gpt-oss:20b`）
- `OPENAI_API_KEY`: 不要

疎通確認: `echo "テスト" | node .claude/skills/watch/scripts/ask-gpt.mjs`

### OpenAI API を使う場合
- `OPENAI_API_KEY`: 環境設定に環境変数として登録する（チャットには貼らない）
- `OPENAI_MODEL`: 省略時は `gpt-4o`
- クラウド環境では `api.openai.com` を許可ドメインに追加する
