# /watch — 停滞監視と自律前進

使い方: `/watch <対象> [間隔]`

- `<対象>`: PR 番号・PR URL、ブランチ名、タスクファイル（例 `TASKS.md`）、または作業内容の説明
- `[間隔]`: `30m` / `2h` など。省略時は `30m`

## 1 回のチェックで行うこと

### 1. 状態を集める
対象に応じて現在の状態を確認する。

- **PR**: GitHub MCP ツールで CI 結果、レビューコメント、マージ可否（コンフリクト）、最終更新日時
- **ブランチ**: `git fetch` → 直近コミット、未プッシュ差分、ビルド・lint・テストの結果
- **タスクファイル**: 未完了項目と、その項目の最終更新

前回チェックの結果は `.claude/watch/STATE.md` に記録されている。前回と比べて何が変わったかを見る。

### 2. 止まっているか判定する
次のどれかに当たれば「停滞」とみなす。

- CI が赤のまま、またはコンフリクトのまま
- 未対応のレビューコメントがある
- 前回チェックから進捗がなく、残タスクがある
- エラーや失敗ログで作業が中断している

停滞がなければ STATE.md に「変化なし」と記録して手順 6 へ進む。ユーザーには報告しない。

### 3. GPT と協議する
停滞の要約を作り、GPT に相談する。相談方法は次の優先順で選ぶ。

#### A. ブラウザで ChatGPT に相談する（既定）
Claude in Chrome（`mcp__claude-in-chrome__*` ツール）が使えるときはこの方法を使う。ユーザーがログイン済みの ChatGPT を操作する。

1. 使う前に `anthropic-skills:chrome-browser` スキルを読み、その手順に従う（最初に `tabs_context_mcp`、作業は新しいタブで）
2. `.claude/watch/STATE.md` に協議用の会話 URL（`https://chatgpt.com/c/...`）があればそれを開く。なければ `https://chatgpt.com/` を開き、送信後の URL を STATE.md に記録して以後も同じ会話を使う
3. 下の「相談内容の書式」で入力欄に貼り付けて送信する
4. 返答の生成が終わるまで待つ（停止ボタンが消え、返答末尾が変化しなくなったら完了）。`get_page_text` か `read_page` で最後の返答を読み取る
5. 再質問は同じ会話で続ける。終わったら自分で開いたタブを閉じる

止まったら次の 3 つを試す。
- ログイン切れ、CAPTCHA、利用上限に当たった場合: 回避しない。STATE.md に記録して B に切り替え、ユーザーに一言だけ伝える
- 拡張が応答しない場合: B に切り替える
- 同じ操作が 2〜3 回失敗した場合: B に切り替える

#### B. API で相談する（ブラウザが使えないとき）
相談内容を標準入力で渡す: `node .claude/skills/watch/scripts/ask-gpt.mjs < 相談内容`
再質問は `--followup` を付けると前回の文脈を引き継ぐ。終了コード 2（未設定）か 3（接続失敗）なら C へ進む。

#### C. 単独で判断する
A も B も使えないとき。その旨を STATE.md に 1 回だけ記録し、Claude 単独で判断して続行する。

#### 相談内容の書式
ブラウザの新しい会話では、先頭に回答形式の指示を付ける（API では ask-gpt.mjs が自動で付ける）。

```
（ブラウザの新しい会話のみ）あなたはソフトウェア開発の相談役です。別の AI エージェント（Claude）が作業の停滞を報告します。
「原因分析」「推奨案（理由つき・優先順）」「リスク・注意点」「人間の判断が必要か（必要/不要と理由）」の見出しで簡潔に答えてください。事実が足りなければ推測で埋めず「追加で確認すべきこと」を挙げてください。

## 対象
## 現状（事実のみ: エラーログ抜粋、CI 結果、差分の要点）
## 止まっている理由についての Claude の見立て
## Claude の案（複数あれば列挙）
```

送らないもの: API キー・トークン・パスワード・個人情報。ログに含まれていたら伏せてから送る。

#### 回答の扱い
- GPT の回答はあくまで参考意見として扱う。自分の分析と突き合わせて、根拠のより強い案を採る
- 意見が割れたら、論点を絞って 1〜2 往復まで再質問する

### 4. 実行する
決めた案を実行する。

- 修正 → リポジトリのチェック（lint / typecheck / build / test）を通す → コミット → 指定ブランチへ push
- push 前に差分を見直し、CI に落とされる要素がないか確認する
- テストをスキップ・無効化して緑にすることはしない

### 5. 具申するかどうか
次の場合**だけ**ユーザーに具申する。それ以外は黙って進める。

- 本番デプロイ、データ削除、force push、課金、外部への公開など、取り消しにくい操作が必要
- 仕様や方針、プロダクトとしての判断が必要（どちらの挙動が正しいか決められない）
- 認証情報、権限、アクセス許可が足りない
- Claude と GPT の意見が重要な点で割れ、再協議しても収束しない
- 同じ停滞に 3 回続けて手を打っても解消しない

具申には「何が止まっているか」「検討した案（Claude 案・GPT 案）」「推奨案と理由」「必要な判断」を短くまとめる。

### 6. 記録して次回を予約する
`.claude/watch/STATE.md` に今回のチェック結果を追記する（日時、状態、行った対応、GPT 協議の要約）。

次回チェックの予約:
- `/loop` 経由で動いている場合は `ScheduleWakeup` で次回を指定する
- それ以外は `send_later` で `[間隔]` 後に「`/watch <対象> <間隔>` の定期チェック」を自分宛てに送る

止める条件:
- 対象が完了した（PR がマージ／クローズ、タスクがすべて完了）
- ユーザーに止めるよう言われた
- 「変化なし」が 3 回続いた → ユーザーに一言だけ伝えて停止

## 設定

### ブラウザの ChatGPT を使う場合（既定）
- PC の Chrome に Claude in Chrome 拡張を入れ、同じ Claude アカウントでサインインする
- Chrome で chatgpt.com にログインしておく
- 拡張から chatgpt.com の操作を許可する
- `/watch` 実行中は PC と Chrome を起動したままにする（スリープすると協議できず、B か C に切り替わる）

### ローカル GPT「Dot」を使う場合
Dot は外部 API を持たないため、Dot と同じモデル（GGUF）を llama.cpp で API として公開して使う。
PC 上で動く Claude Code セッション（Claude Desktop アプリ、または `claude remote-control`）で行う。

1. llama.cpp をインストール（macOS: `brew install llama.cpp`、Windows: `winget install llama.cpp`）
2. 別ターミナルでサーバーを起動したままにする: `node .claude/skills/watch/scripts/dot-server.mjs`
   - モデルは Dot の設定（設定画面で選んだファイル）→ `書類/Dot-Data/*.gguf` の順に自動で探す
   - 見つからなければ `DOT_MODEL_PATH` で指定。見つかったパスの確認は `--print`
3. Claude Code 側で環境変数 `WATCH_GPT=dot` を設定する（ポートを変えたら `DOT_PORT` も）
4. 疎通確認: `echo "テスト" | WATCH_GPT=dot node .claude/skills/watch/scripts/ask-gpt.mjs`

`/watch` の各チェックの最初に `curl -s http://127.0.0.1:${DOT_PORT:-8089}/health` でサーバーの生存を確認し、
落ちていれば `dot-server.mjs` をバックグラウンドで起動し直してから協議する。

### ローカル GPT（この PC 上の Ollama / LM Studio など）を使う場合
ローカル GPT には PC 上で動く Claude Code セッションからしか届かない。クラウドセッションからは使えない。
Claude Desktop アプリ、またはリポジトリのフォルダで `claude remote-control` を起動して、そのセッションで `/watch` を使う。

環境変数（PC 側で設定）:
- `OPENAI_BASE_URL`: OpenAI 互換エンドポイント。Ollama は `http://localhost:11434/v1`、LM Studio は `http://localhost:1234/v1`
- `OPENAI_MODEL`: モデル名（必須。例 `gpt-oss:20b`）
- `OPENAI_API_KEY`: 不要

疎通確認: `echo "テスト" | node .claude/skills/watch/scripts/ask-gpt.mjs`

### OpenAI API を使う場合
- `OPENAI_API_KEY`: 環境設定に環境変数として登録する（チャットには貼らない）
- `OPENAI_MODEL`: 省略時は `gpt-4o`
- クラウド環境では `api.openai.com` を許可ドメインに追加する
